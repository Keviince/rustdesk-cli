# v0.1.1 — self-hosted relay connection fixes

This release of the Keviince fork fixes relay negotiation that could previously try to connect to `:21117`, or lose the relay UUID when the peer acknowledged a relay request without echoing its fields.

- Add `--relay-server`, `RDC_RELAY`, and config `relay_server` with flag → environment → config precedence.
- Use the announced relay when available; otherwise derive the rendezvous host and port plus one. Independent relays and custom port mappings can be explicitly configured.
- Coordinate the selected relay address and UUID with the controlled peer, retain them across empty acknowledgements, and preserve signed peer identity during relay fallback.
- Keep force-relay rendezvous negotiation and existing login-token authentication.
- Restore config-file `server`/`key` handling, the CLI entry point, version reporting, and documented exit codes.
- Repair the binary ignore rule and gate releases on build, test, and vet checks.
- Restore Windows source compilation with a platform-specific socket option adapter; release binaries target Linux and macOS.

## Downloads

`rdcli-linux-amd64`, `rdcli-linux-arm64`, `rdcli-darwin-amd64`, `rdcli-darwin-arm64`, and `checksums.txt`.

## Validation and compatibility

Regression tests cover address validation, configuration precedence and persistence, normal and empty relay acknowledgements, automatic relay derivation, direct-connection fallback, forced relay, explicit overrides, UUID pairing, encrypted token-authenticated rendezvous, and encrypted terminal sessions. Existing file-transfer and tunnel tests are also run.

The release workflow runs build/test/vet checks on Linux and macOS, cross-compiles all four binaries, runs the Linux amd64 version smoke check, and verifies checksums before publishing.

**No connection to a real self-hosted RustDesk server or Windows controlled device has been tested.** Mock protocol coverage does not establish compatibility with every deployment. First verify a harmless command such as `whoami` on one device before using your existing batch-update scripts. Terminal sessions require a peer version of at least 1.4.1.

Protocol references: RustDesk 1.4.1 [`src/client.rs`](https://github.com/rustdesk/rustdesk/blob/1.4.1/src/client.rs) and [`src/rendezvous_mediator.rs`](https://github.com/rustdesk/rustdesk/blob/1.4.1/src/rendezvous_mediator.rs).

# v0.1.2 — headless account login

Adds `rdcli auth login` for lejianwen/rustdesk-api and compatible self-hosted RustDesk API servers.

- Supply the API URL and username with `--api-server` and `--username`/`-u`.
- Supply the account password with `--password-stdin`, `RDC_API_PASSWORD`, or `--password`/`-p`. Peer passwords continue to use `RDC_PASSWORD`.
- Save the access token and login settings, reuse a stable device UUID, and preserve the previous configuration when login fails. The supplied account password is not saved.
- Support `RDC_API_SERVER`, `RDC_API_USERNAME`, remembered login settings, and JSON success output.
- Verify HTTPS certificates, reject credential redirects, and require explicit `--allow-http` for trusted non-loopback HTTP deployments.
- Fix `auth status` token-source reporting and mask its JSON token field. Config files use owner-only permissions on POSIX systems.

Example after obtaining the password in `RDC_API_PASSWORD`:

```sh
rdcli auth login --api-server https://api.example.com --username alice
rdcli auth status
```

Existing `--token` and `RDC_TOKEN` overrides still take precedence over the newly saved token. Additional-verification or SSO-only deployments can use `auth set` or `auth import-gui`.

## Validation and downloads

The account-login implementation passed local build/test/vet checks and Linux/macOS CI. Mock API tests cover successful login, credential precedence, password input, token persistence, rejected credentials, verification challenges, malformed responses, timeouts, redirects, and TLS validation. A real self-hosted server has not been tested.

The tag workflow builds and uploads Linux/macOS binaries for amd64 and arm64, plus `checksums.txt`, after its validation jobs pass.
